# Design · 一台统一的复古电视，而不是一组复古网页按钮

版本：1.0 / 2026-09-16。以下具体造型、色值和尺寸为**建议设计**，等待Q01–Q03及控件小样审核，不是用户已经批准的图纸。

## D01 · 采用哪一版，不能凭文件名决定

main保留历史生产基础；PR #14当前 `a3f9b5d7e3a73c1587b3ca86d7f5393351e427ac` 是正面机身和播放修复候选；聊天V3是去页眉、实体键帽和完整启动逻辑的审查输入。两者不可互相冒充。

实施前在独立工作树读取最新PR #14，提取V3相对于该版本的差异，保留它已经解决的启动停表、焦点、键帽分层和手机本体操作；同时修复本轮确认的问题。不要以新生成图重写16幕，不把单文件重新当作唯一生产源码。旧照片、旧HTML及冻结baseline不改。

本规格只列如何对齐，尚未执行这些生产修改。恢复源码和判断文件归属由开发者完成，不把搬运工作再转给用户。

## D02 · 构图与深度

### 正面规则

主体仍是大屏；物理控制在正面右侧条带，而不是放到侧壁。显示面四边平正，所有可读内容不施加透视变形。屏幕与菜单不得为模仿曲面而弯曲文字。

使用固定的浅层斜投影表现后壳。推荐在机身宽约1160px时，后壳向右约24px、向下约8px；窄屏同比减至约10px/3px。该方向沿用PR #14正面修正的思路。不是浏览器相机的真实正投影；它是一种前平面保持不变的插画约定。

后壳、前后脚和控件厚度必须依据同一个前后方向检查。按键压入朝安装面收拢，高光与侧壁一起变化；阴影由左上光源产生，不能把阴影方向误当作机身透视方向。参数允许小样微调，但不允许不同部件各自任选方向。

### 画面层次

从后向前：中性环境与接触影 → 后壳/后脚 → 前壳/前脚 → 屏框斜面与玻璃 → 原节目画布 → 克制玻璃反光/扫描线 → 屏内操作层 → 启动/待机状态 → 屏内对话框。

装饰无pointer事件，不遮挡点击和焦点环。外轮廓清楚，内框光暗方向一致；脚底要有短接触影，整体软影可以扩散，但不能靠大模糊让电视悬浮。

桌面建议机身外宽1000–1200px范围自适应，显示面占前壳宽约77%–81%，控制区约13%–15%；余量用于内框和间距。这是构图起点，不作为迫使小窗口截断的硬宽度。

## D03 · 材质、颜色、线条与字形

### 角色先于色值

| 角色 | 建议颜色 | 使用位置 | 禁止的混用 |
|---|---|---|---|
| 环境 | `#EDE6D8`，亮部`#F8F4EA` | 电视外部背景 | 不加网页分区、桌面图标或无关道具 |
| 奶油外壳 | `#F2E8D4`，亮部`#FBF5E7`，暗部`#CFBE9B` | 机身、操作面板 | 不每个部件随意另调黄度 |
| 象牙键帽 | `#E6D8B9`，亮部`#F8F1DF`，暗部`#CDB891` | 四主键同一材质 | 不再四色整面并列 |
| 深橄榄/炭色 | `#373A2F` / `#35372D` | 印字、内框、旋钮握柄、凹槽 | 不使用纯黑粗线覆盖所有细节 |
| 暖金属 | `#A58B59`，亮部`#D6C18E`，暗部`#746042` | 旋钮环、螺丝和天线细节 | 不同时叠加亮黄金、冷银和泛蓝镀铬 |
| 木/棕色 | `#8A6844`及同族阴影 | 提手与脚局部 | 不增加木纹贴图拼贴 |
| 状态橄榄 | `#657351`，亮部`#CBD4AE` | 小指示灯/选中刻度 | 不占整块键面 |
| 电源提示 | `#9C5F47` | 小圆点、细标记 | 不把整个电源键染成高亮糖果红 |
| 屏内操作层 | 底`#23372C`，字`#EEEBD8`，次字`#C1CAAE` | 菜单、提示、状态字 | 不复制塑料键的厚阴影 |
| 焦点 | 深底`#E5C982`，浅底`#465A37` | 清晰可见的键盘焦点 | 不靠默认浏览器蓝框偶然决定风格 |

这些不是从外部照片精确采样得到的色卡，而是待审核的本项目值。项目主题值与原节目主题分开，避免强制把课程、曲线和预告都染成奶油色。所有关键文本还需对实际背景做对比测试。

机身主导奶油，深内框形成结构，少量金属与木色解释零件；状态色只承担信息。多个材质共存并非错误，错误是没有明确使用部位和共同光照。

### 线条与质感

外轮廓约1.5–2px、结构分缝约1px、局部磨损0.6–1px起步；只对非交互轮廓做小幅偏移，不能所有边框都画成两道等距圈。左右轮廓可以有轻微手工差别，但按钮装配与字形不能歪。

壳体磨损只留在边缘、提手接触处和少量轮廓，不铺满屏幕。键帽采用较宽的柔和亮区，删掉现有糖果式条状镜面高光。高光/阴影通过统一的方向与尺度定义，不靠不断追加box-shadow。

卡通感来自圆润体量、轮廓略夸张、零件动作清楚；不等于果冻弹跳、大量贴纸、满屏涂鸦或所有文字改手写。

### 字体与图标

中文操作字统一13–14px、500或600字重，手机不降到难读的小字；输入框手机保持至少16px。数字与频道刻度使用同一等宽数字方案。字标可以采用小范围手写风格，但须确认本机实际字形；没有该字体就使用设计好的系统回退，不把字体文件打包。

图标统一18–20px视框、约1.8px线重与端点处理，作为印刷图案落在键面。不要电源粗实线、菜单极细线、外链又是不同角度的斜箭头。图标含义保持现有四功能，不因美术更换成心形/星形分类而改变导航含义。

## D04 · 控件家族：先审这一组，再改整机

### Q01推荐方案A：同族机械键

四键采用浅象牙的短圆角长方形，带轻微弧面而非半圆封头。桌面安装座约150×52px、键面约140×40–44px，圆角约8–11px；组内间距8–10px。尺寸与原控制条带相近，避免为追求复古而把屏幕挤小。

物理层次沿用V3已有的安装座/侧壁/键帽，但重新定形：凹槽只显示窄暗线；侧壁厚度有限；键帽顶面不使用四色。印字位置、线重、高光宽度、端面角度一致。参考Braun SK4的是零件家族和克制标识，不复制其整机布局、字体或品牌。

备用方案B：更贴原始图片，保留奶油胶囊主体，只让图标端有很小的低饱和色区。B不是当前四个全彩胶囊，也不和A同时开发。选择B后先更新本节几何与色卡，再做小样。

### 状态必须符合动作含义

| 控件 | 可见固定标识 | 状态与行为 | 原生语义 |
|---|---|---|---|
| 电源 | 电源符号＋电源 | 稳定灯表示开启；按下只短暂压入；启动中关闭立即停止 | button，固定label，aria-pressed表示电源状态 |
| 播放 | 播放/暂停符号＋播放/暂停 | 小状态标识区分用户播放意图和暂停；菜单停表不能改用户意图 | 推荐固定label和aria-pressed；aria-describedby解释系统暂停/菜单状态 |
| 节目表 | 同族列表符号＋节目表 | 打开屏内节目表/设置；关闭返回原控件 | button，aria-haspopup="dialog"，aria-expanded |
| 打开工具 | 同族外链符号＋打开工具 | 已接入是安全新标签链接；未接入进入配置并说明 | 配置后使用a；未配置用button，同外观、不嵌套交互元素 |

当前V3的播放键同时改变label和aria-pressed，应择一规范化。本稿推荐固定印刷文字，更符合实体标签；如果用户选择动态文案，则改成普通动作button、不使用aria-pressed，不能两套语义混搭。[N01]

### 动作与焦点

休止：活动键面高于安装座，光照稳定。悬停：至多轻微亮度变化，不浮起。按下：键面向安装座收拢约1–3px，外部安装座不动；字和图标与键面同动。松开：90–140ms内回到休止，无多次弹簧震荡。持续状态用小灯或标记表示，不把瞬时按下与锁定状态混为一谈。

这些时值是建议范围，不是已经测出的性能。减少动态时直接换状态，焦点环和标签不受影响。按下中指针取消/移出必须清理暂态，不能留下永远压住的键面。

### 旋钮、刻度、扬声器

旋钮继续是频道选择主控，直径约72–82px。刻度1–7等分，指针指向对应刻度，跨7/1按最近连续方向转动，不转整机。旁边保留可点击的前/后操作，拖动不是唯一方法。[N09]

频道窗只显示台号/简短状态，不展示虚构在线人数或信号强度。旋钮环、螺丝、天线采用同一暖金属家族；握柄与屏框同族深色。

扬声器孔洞应是内凹结构而非重复黑白条贴纸；孔宽、间隔、边缘高光与周边材质协调。轮廓可偏圆/椭圆，但不能新增假音量控制。本轮不加开机音或点击音。

## D05 · 屏内操作层

常态尽量完整播放节目；辅助条只在需要时出现，按键焦点在其中时不能消失。把它当屏幕上的操作文字，不仿成第二排塑料彩键。暂停原因短且明确，播放入口可见；不要让大提示长期盖住节目关键位置。

节目表保持七频道及直接打开入口。设置保持画面、接入、说明，草稿跨页签保存，未保存关闭有选择。屏内对话框使用深橄榄底、暖白文字、克制分隔线，不增加发蓝玻璃或另一套大圆角阴影卡片。

采用一个实际可达的模态范围：启动后进入对话框焦点；对话框之外的机身、辅助条和背景不可交互；Tab不逃逸；Escape按草稿状态关闭或提示；关闭恢复触发控件或屏幕。不要只将右侧机身inert而漏掉辅助条。[N06]

全屏是可选操作，不自动请求浏览器全屏。全屏进入/退出仍保留关闭、播放、菜单等路径。无页眉的日常沉浸布局与“只看画面”的可选全屏状态不能继续共用含义含混的immersive设置。

## D06 · 导航与输入

所有换台入口统一调用频道动作；机身只显示状态并发送动作，不维护第二套channel、不自行打开网址。菜单输入框不触发全局1–7快捷键。每次变更同步更新频道窗、指针、辅助信息与真实链接。

转场沿用短暂横向同步错位/消隐的方向，建议200–320ms；起点应是当下的合成画面，旧转场被新意图取消。最后一次选择始终生效；不得使用“TUNING…”阻塞弹框代替节目过程。

打开工具按当前真实配置完成，开机/换台都不能增加等待。未配置是“需要配置”，不是“离线”；不做未经测试的在线检测。保留地址校验与安全链接处理，绝不自动把.top改.com。

## D07 · 启动与播放状态

### 状态不是一只paused布尔值

至少区分：power、boot phase、当前频道/分幕、节目elapsed、用户播放意图、菜单暂停、页面隐藏、系统减少动态、初始海报是否尚未主动播放、当前转场版本。可以在现有runtime内增量实现，不要求先拆出一套新播放器架构。

运行条件：电源开、启动完成、用户允许播放、菜单关闭、页面可见。开机时间与节目时间分开，但由同一宿主rAF推进；不要建立独立setInterval或每个频道私有时钟。[N08]

### 建议普通开机时间线

| 区间 | 画面 | 节目时间 |
|---|---|---|
| 0–120ms | 关闭的显像面与克制中心亮点 | 0 |
| 120–360ms | 柔和横线出现 | 0 |
| 360–850ms | 显像区域展开，无全屏闪白 | 0 |
| 850–1400ms | 短暂JCLAW台标/画面稳定 | 0 |
| 1400–1700ms | 与当前第一幕衔接 | 0，结束后才正常推进 |

该序列是拟物表达，不是对某一历史电视电子电路启动速度的科学复现。禁止反复强闪或纯红闪；开启减少动态时约220ms短淡入，不做扫描展开。[N04][N07]

初始HTML/CSS已覆盖显像面，避免首帧漏出节目。刷新重复同样过程；离线亦能完成；跳过不额外等待。开机无需音频自动播放权限。

### 冲突动作的唯一结果

| 开机中发生 | 结果 |
|---|---|
| 电源关闭 | 取消开机和转场，保持关机；旧时长到期不能复活 |
| 再次开机 | 新建启动阶段，沿用明确的当前频道/分幕状态 |
| 跳过 | 完成启动，按用户播放意图进入节目 |
| 直接换台 | 结束启动后立即切到请求频道，第一幕从0开始 |
| 打开节目表 | 结束启动，打开菜单，节目停表 |
| 打开工具 | 结束启动并在本次用户激活事件内导航，不延迟弹窗 |
| 播放/暂停键 | 结束启动并切换用户意图，界面立即反映结果 |
| 页面隐藏 | 开机和节目都停表，回来继续，不补算后台时间 |

系统减少动态下可以呈现第一幕静态预览。但首次主动播放必须从0开始，避免当前V3从7.2秒位置只播放余下约2.8秒。此重置只适用于初始海报，不适用于用户随后手动暂停/继续。系统设置改变不能把用户暂停清除。

默认的自动切换仅在当前频道的分幕内进行。保持6/3/3/1/1/1/1，不新加七频道自动巡播。分幕自动切换偏好与播放意图分别命名；即使旧存储字段autoplay沿用，界面应解释它控制“切幕”，而非电源或启动。

## D08 · 节目审查与保真

本次已检查16幕在桌面和手机的对照，并以真实时间检测主体像素变化。保留独立网站模块及主题。颜色统一不可以改动演示数据、图例含义、统计范围或临床结论措辞。

当前手机里的刻度、注释、课程字幕等仍偏小；这属于后续网站画面专项，记录入口为原Issues #2–#8。先通过当前轮机身任务，再逐网站调整布局和可读性；不在一次CSS外壳修改里暗改16幕内容。

保真有两条证据：同画布尺寸、同时间点的原节目像素对照；无seek、无测试时钟加速的真实主体动作录像。前者不能证明动画在动，后者不能证明所有文字正确，两项都要有。

## D09 · 响应式与可读性

基础验证视口：1920×1080、1440×900、1280×720、1024×768、768×1024、390×844、320×740、844×390、640×480。另测浏览器200%缩放、系统减少动态、键盘操作及触屏模拟；Safari/iOS真实设备应在发布前补测。

宽屏右侧窄控制列；手机把同族四键收进下方机身，保持顺序与材质。不因为换行就从细长机械键变成四块大糖果。空间不足时两行有序排列，保留小频道标识和换台路径，非必要提手/扬声器可简化。

主触控区域目标44×44px，注意圆角后实际可点区域；该值为项目要求，高于WCAG2.2的AA最低目标尺寸。[N02] 文本4.5:1、大文本3:1按实际叠层检查。[N05] 辅助线和装饰不要求全部达到文字对比度，不能用提升所有线条对比来制造脏乱。

页面不能靠禁止滚动掩盖控件截断；菜单长列表能滚到第七台，软键盘弹出时输入与保存仍可到达。桌面投影方向、图标家族和字重在窄屏继续成立。

## D10 · 实现形式与外部资源取舍

默认继续原生HTML/CSS表现外壳和控件、Canvas渲染既有节目。无需为“3D”安装新引擎。组件共享token与状态定义，生产源码不累积一层又一层覆盖CSS；固定旧画面比较通过后再单独做视觉修改。

Rough.js可以评估为离线生成少量稳定轮廓的工具，但不是必须运行依赖；不每帧随机变化，不处理小字。[E04] Zdog说明伪3D表达可行，但其旋转示例与本项目正面稳定要求冲突，本轮不引入、更不复制dragRotate。[E05]

外部实物照片只作研究依据，除非许可已确认，不复制为皮肤、不热链成运行时资源。生成图只能为审批提供草图；真实按钮、标签、菜单与导航必须原生可操作。不要把整张图切热点作为“已实现”。

## D11 · 视觉与功能分开审核

先审控件板：一个旋钮、四主键、频道窗、扬声器、字标的休止/按下/聚焦态。确认同一台设备的材料、装配方向和颜色，再扩到整机。之后对桌面/手机、浅色/深色节目、菜单、开机、待机做整机检查。

每次提交附具体差异，不用“更高级、更复古”代替说明。最终一套记录须同时包含：批准的样式来源、准确源提交、构建HTML、真实截图、真实动作录像、已测/未测项与用户审核结论。生成图与浏览器图必须显式区分。
