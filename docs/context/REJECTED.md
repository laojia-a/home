# 已否定方案与可保留部分

这里记录原因，防止接手者只看到漂亮文件名就重新采用。不删除已有来源，不把被否定版本作为当前生产实现。

| 方案/做法 | 被否定或纠正的原因 | 可以保留什么 |
|---|---|---|
| 只给概念图 | 用户要可运行交互网页 | 可记录视觉试错，不能当实机证据 |
| 多套背景配同一布局 | 风格差异肤浅、刻板 | 色彩候选，不继承同质化结构 |
| 复古/macOS仅换色 | 用户明确是两个独立方向 | 独立图标与菜单组织经验 |
| jclawOS不断增设应用、窗口、工坊 | 导航变成需学习管理的系统 | 图标、主题、字体规则、局部反馈 |
| 为手绘铺满粗字、未加载字体也称完成 | 小字不清晰，中文效果未实际出现 | 加载状态/回退和本机字体策略 |
| 鹈鹕主角版、精修保留积累版 | 把借鉴动作语言误读为加入鹈鹕、改绘本风 | 线条尝试；不继承其界面简化 |
| 内核回归版/vNext | 没有真正用更成熟母版，画面退成左右卡片，交互缩水 | 记录反例，不以名字当新基准 |
| 只加几层阴影和TUNING弹框 | 并非充分动作打磨，未保留节目式内容 | 无需整套迁移 |
| 换台期间锁输入 | 丢掉快速连续选择 | 改为最后选择生效/取消旧转场 |
| 归档只放相对链接 | 发布包没有目标文件，等于积累没带走 | 采用实际文件/可重建且校验的包 |
| SOURCE/PLAN旧状态留在根文件冒充当前 | 会导致接手AI重复导入旧src | 历史快照移docs/history，当前状态独立 |
| 用测试数量回答“不精细” | 行为验证不能证明审美 | 技术证据保留，视觉另看连续画面 |

用户没有要求永远禁用3D、Doodle、动效或高品质材质。否定的是偏离导航、粗糙、同质化、误读参考和交互退步，不是把页面改回普通网址列表。

本文件不会把某次截图或助手的自评升级为用户最终验收；当前视觉仍需实际打磨和确认。
