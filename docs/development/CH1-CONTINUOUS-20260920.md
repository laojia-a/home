# CH1 六幕接续设计与接入

用户要求六幕不要生硬切换，并连续播放。本次从已审阅的合同 v10、血浆 v4、例数 v6、CTCAE v7、术语 v8、餐谱 v9 接入模块。

## 接续方式

1. 以研究准备、执行操作、记录核对分组，形成理解顺序；不把栏目顺序描述成实验 SOP。
2. 每幕先给短开场卡片，再播放完整正片，结束后保留 1.1 秒阅读时间。
3. 末尾 0.9 秒将终帧叠化成下一幕卡片；下一幕从同一张卡片淡入正片，没有黑场或跨场景双重文字。
4. 台标固定，开场与接续期间隐藏旧分幕小标题，避免与即将进入的节目名称冲突。
5. 自动转场使用正片的同一个时钟，暂停即冻结；手动切幕使用 0.4 秒 UI 叠化并保留暂停意图。
6. 时钟跨场景保留余量，关闭自动轮播则本幕平滑循环。

开场 850 ms + 原内容 + 收尾停留 1100 ms + 接续 900 ms，总计 145100 ms。

## 模块与检查

- 正文绘制按目录保存到 `src/animations/sites/cth/scenes/`，仅调整 import 路径与模块导出形式；示例数据保持原值。
- 画布适配器负责开场、停留与接续，场景不挂自己的计时器或全局监听。
- 六个边界含最后回到第一幕，新增实际浏览器像素比较；另查暂停、恢复、手动切幕、自动推进、关闭轮播。
- 原节目基线校验继续用于未改动的 CH02–03；CH1 已是明确的视觉改版，不再冒称与原版像素一致。
- 构建和单元检查已在本机通过；浏览器 CI 结果另按实际运行记录。

当前发布边界：本地审阅与私有分支。此前授权的 MedDRA 单例数据仍限私有仓库，未对公开站点部署作新授权。
